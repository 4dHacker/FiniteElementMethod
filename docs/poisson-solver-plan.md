# Minimal, verified 2D Poisson solver

Status: implementation and acceptance plan, not a completed solver.
The local element is now implemented; see element-hand-check.md and element.hh.
Prepared on 2026-11-11 for the AI contribution.

Basis: Peter Bastian, *Minimal Finite Element Formulation*, 4 November 2026,
three-page handout supplied by the user. Follow its reference-element method
and its three interior quadrature points. This document defines the software
workflow; it does not define a lecture schedule.

## 1. Keep the first release small

Solve

\[
-\Delta u=f\quad\text{in }\Omega\subset\mathbb R^2,
\qquad u=0\quad\text{on }\partial\Omega.
\]

Use double precision, conforming straight-sided P1 triangles, the existing
Gmsh MSH 2.2 ASCII reader, HDNUM sparse matrices and sparse LU, and legacy
VTK output. Set the handout's scalar coefficient K to 1.

Allow the source f(x,y) to change without changing assembly. Keep variable K,
mixed/Neumann conditions, nonzero Dirichlet data, time dependence, higher-order
elements, 3D, iterative solver selection and a GUI outside this release.
If the existing Problem interface supplies g, reject nonzero boundary values
explicitly until they are supported; never silently replace them by zero.

## 2. The complete executable workflow

```text
mesh.msh + f(x,y)
    -> read Mesh
    -> validate triangle topology and exterior boundary
    -> compute local stiffness matrices and load vectors
    -> accumulate the global sparse system
    -> impose homogeneous Dirichlet conditions symmetrically
    -> solve using HDNUM sparse LU
    -> check finiteness, residual and boundary values
    -> write solution.vtk and a short numerical summary
```

The executable should have one simple entry point:

```text
fem2d mesh.msh solution.vtk
```

Use f=1 as the default demonstration problem, as in the existing problem.hh.
Use a separate test problem with a known solution for verification.
Report failure with a clear message and nonzero exit status. Do not export a
solution after a failed validation or solve.

## 3. Mesh preparation

Preserve the shared Mesh fields: points, triangles and on_boundary.
Triangle indices are the handout's local-to-global map g(k,i).

Before assembly:

- Check index bounds, finite coordinates and nonzero triangle area.
- Normalize clockwise triangles to counter-clockwise by swapping corners 1 and 2
  in the assembly's local copy; the reader may preserve the file ordering.
- Reject duplicate cells, unused vertices and edges shared by more than two cells.
- Count triangle-edge incidences. Edges incident on one triangle define the
  exterior boundary, including hole boundaries. Derive the solver's boundary-node
  mask from these edges, rather than treating every tagged interior curve as an
  exterior boundary. This does not require a public Mesh-interface change.
- Reject a component without a Dirichlet anchor. A mesh with all vertices on
  the boundary is valid, but its solution is identically zero for this release;
  report that it has no interior degrees of freedom.

Assume the input is a conforming, non-overlapping triangular mesh generated by
Gmsh. Basic validation does not prove this geometrical assumption. Avoid a full
CAD/topology repair system; state the accepted input clearly.

## 4. Reference data: define once

Reference vertices are (0,0), (1,0), (0,1). Shape functions and gradients are

\[
\hat\phi=(1-\xi-\eta,\xi,\eta),\qquad
\hat G_0=(-1,-1)^T,\quad\hat G_1=(1,0)^T,\quad\hat G_2=(0,1)^T.
\]

Use the handout's rule, not the edge-midpoint alternative discussed earlier:

| q | Reference point (xi, eta) | Reference weight |
|---|---|---|
| 0 | (1/6, 1/6) | 1/6 |
| 1 | (2/3, 1/6) | 1/6 |
| 2 | (1/6, 2/3) | 1/6 |

Precompute Phi[i][q] = phi_i(reference_point[q]). The reference weights sum to
1/2, the reference-triangle area, not to 1.

## 5. One triangle: geometry, local matrix and local load

For vertices y0, y1, y2 in counter-clockwise order, form

\[
B=[y_1-y_0\; y_2-y_0],\quad d=\det B>0,\quad |T|=d/2,
\qquad \mu_T(\hat x)=y_0+B\hat x.
\]

Transform the three constant gradients with the inverse transpose:

\[
G_i=B^{-T}\hat G_i.
\]

Compute the local stiffness matrix exactly, since K=1 and gradients are constant:

\[
E_{ij}=\frac d2\,G_i\cdot G_j.
\]

Map each quadrature point into the physical triangle, evaluate f there, and use

\[
r_i=d\sum_{q=0}^{2}w_q\,f(\mu_T(\hat x_q))\,\hat\phi_i(\hat x_q).
\]

Only one factor d is required. For constant f, r_i=f|T|/3 exactly.
For nonpolynomial f, this rule is an approximation, not an exact integral.

Notation clarification for the supplied handout: use B^{-T} in step 3e,
consistent with step 3d and the chain rule. Use the current quadrature point
inside every summand and its weight w_q. The printed quadrature expression
repeats one point, and the load expression labels the weight w_i; the formulas
above make the intended summation explicit.

## 6. Global assembly and boundary conditions

Create one HDNUM SparseMatrix<double>::builder of size N by N and a zero
hdnum::Vector<double> of length N. For each triangle, accumulate:

```cpp
builder[g(k,i)][g(k,j)] += E[i][j];
b[g(k,i)] += r[i];
```

This is schematic indexing; use mesh.triangles[k][i] for g(k,i).
Important: HDNUM builder.addEntry uses map.emplace and does not add a new value
to an already existing entry. Repeated addEntry calls are not FEM accumulation.

For the first release's zero Dirichlet conditions, the simplest symmetric
implementation is to accumulate matrix entries only when both global nodes are
interior, and load entries only when their row is interior. For each boundary
node insert A[i][i]=1 and b[i]=0. The resulting full-size system is equivalent
to zeroing boundary rows and columns and setting their diagonal to 1.
No load correction is needed because all prescribed boundary values are zero.

Call builder.build() once after assembly. Do not change the shared Mesh or
LinearSystem signatures, and do not create a dense global matrix.

## 7. Solve and check before exporting

Use the existing HDNUM calls:

```cpp
auto LU = hdnum::sparseLUDecomposition(sys.A);
auto u = hdnum::sparseLUSolver(LU, sys.b);
```

Keep the original constrained A and b for the residual check. Confirm that the
solution and matrix computations are finite, every prescribed boundary value
is satisfied, and

\[
\rho=\frac{\|Au-b\|_2}{\max(1,\|b\|_2)}
\]

is small. Use rho <= 1e-10 as an initial acceptance threshold for the agreed
small, well-scaled test meshes; do not claim this is a universal guarantee.
A small residual alone does not establish correctness of the FEM discretization.

The pinned sparse LU has no general pivoting strategy. Use it for the validated
Dirichlet Poisson systems; detect invalid/singular inputs before solving and
verify the output. It is not a general-purpose sparse solver replacement.

VTK output must contain one value per mesh point and enough numeric precision
for double results (17 significant digits). Check both file opening and final
write status. Report node/triangle counts, interior degrees of freedom and rho.

## 8. Small, meaningful acceptance suite

1. Local element: vertices (0,0), (1,0), (0,1), f=1. Expected values:

   \[
   E=\begin{pmatrix}1&-1/2&-1/2\\-1/2&1/2&0\\-1/2&0&1/2\end{pmatrix},
   \qquad r=(1/6,1/6,1/6)^T.
   \]

   Also test a translated/scaled triangle and reversed vertex order, comparing
   after the corresponding local-index permutation. Check symmetry and zero
   row sums; a local stiffness matrix is singular, which is expected.

2. Quadrature: integrate 1, xi, eta, xi^2, xi*eta, eta^2 on the reference
   triangle. Exact values: 1/2, 1/6, 1/6, 1/12, 1/24, 1/12.

3. Assembly: unit square with four triangles around the center and f=4,
   zero boundary. The only interior coefficient satisfies A_cc=4, b_c=4/3,
   so u(center)=1/3. This matches the hand-computed target in the existing
   assembly test. Check boundary rows/columns as well as the center solution.

4. Zero forcing: f=0, zero boundary. The solution must be zero. Also accept
   the all-boundary mesh without invoking an unnecessary factorization.

5. Manufactured solution on the unit square:

   \[
   u_*(x,y)=\sin(\pi x)\sin(\pi y),\qquad
   f=2\pi^2\sin(\pi x)\sin(\pi y).
   \]

   Use at least three shape-regular mesh levels with approximately halved h.
   Check decreasing error and approximately second-order L2 convergence in
   the asymptotic regime. Use a higher-order rule for test-only error integration
   and check its quadrature sensitivity; do not use visual plausibility or nodal
   agreement alone as the accuracy test.

6. Input/output failures: bad file, unsupported mesh, degenerate cell,
   inconsistent connectivity and unwritable output must fail cleanly. Retain
   all reader regression tests. Check VTK connectivity and point-data count.

## 9. Implementation order and module ownership

| Order | File | Responsibility |
|---|---|---|
| 1 | include/fem/mesh_reader.hh | Existing reader; keep its interface |
| 2 | include/fem/element.hh (new) | Reference rule, geometry, local E and r |
| 3 | include/fem/assembly.hh | Basic mesh checks, boundary mask, sparse accumulation |
| 4 | src/main.cc | Read, assemble, solve, verify, export, handle errors |
| 5 | include/fem/vtk_writer.hh | Validate sizes, preserve precision, check writes |
| 6 | tests/ | Local, assembly, end-to-end and convergence checks |

Keep the existing problem.hh for PDE data and reuse HDNUM for linear algebra.
Avoid extra base classes, plugin systems and new numerical dependencies.
Land tests with each numerical module, not as a final clean-up phase.

Current status: the reader and independent local-element calculation are implemented
and tested; the team's assembly remains a placeholder. The element also accepts
clockwise input directly using the signed inverse and absolute integration measure,
preserving local indexing. This avoids needing a separate orientation change for
the local calculation. This plan does not claim that the full solver is complete.
The AI contribution and human contributions should use common acceptance cases
while retaining separate implementation histories.
